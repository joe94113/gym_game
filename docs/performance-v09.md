# 0.9.0 效能比較

本版完成教室／浴室分區休眠、休眠內容移出渲染走訪、跨器材實例批次，以及矩陣改變時才標記上傳。格局、碰撞與導航保留；人物仍使用原骨架、接點與紅橘肌群標色。模型與貼圖仍常駐，沒有實作資源卸載。

## 同條件前後比較

比較凍結的 0.8.0 原始碼副本和最終 0.9.0。兩版都使用流暢模式、1280 × 800 視窗、DPR 1，實際畫布 1088 × 680，關閉陰影，採相同人物站位與相機。頁面載入前停用自動動畫，改用固定 1／60 秒步進；每個視角先模擬兩秒，讓分區顯示緩衝結束，再暖機 16 格、測量 64 格。

執行環境為 Chromium 的 **SwiftShader 軟體繪圖**。繪製計時包含 `world.update`、渲染呼叫及 `gl.finish` 等待完成，是 CPU 與繪圖工作的整體時間，不是純 GPU 時間，也不能直接當成玩家電腦的 FPS。CPU 更新欄單獨測不繪圖的更新，不包含繪製前的批次處理。

| 固定視角 | CPU 更新中位數，前 → 後 | 整體畫格中位數，前 → 後 | 畫格 P95，前 → 後 | 繪製呼叫，前 → 後 |
| --- | --- | --- | --- | --- |
| 主場館 | 5.5 → 2.4 ms | 29.2 → 24.1 ms | 38.9 → 34.9 ms | 722 → 552 |
| 團課教室 | 1.9 → 2.0 ms | 10.9 → 11.6 ms | 21.4 → 18.8 ms | 179 → 183 |
| 浴室 | 2.1 → 1.3 ms | 4.5 → 3.3 ms | 8.3 → 7.8 ms | 87 → 92 |

這次主場館整體畫格約減少 17％、浴室約減少 27％；教室中位數增加約 6％，P95 則降低。沒有得到所有視角都加速的結果。架構改成按房間合併，部分視角會多幾個呼叫；顯示中的人物仍維持原模型，因此正在上團課時不能省掉教練與學員的主要負載。

主場館最終一格有 276 個相容可見來源，其中 21 個維持原繪製、255 個進入 86 個實例批次；當格只有七個批次需要標記矩陣更新及重算範圍。這是程式的更新標記，不宣稱是驅動程式實際上傳的次數。流暢模式在教室／浴室改用原繪製，回到主場館再恢復批次，避免稀疏視角多做實例運算。

原始數值、全部 64 個樣本、相機、站位、畫布、來源雜湊及分區診斷分別存於 [0.8.0](../artifacts/performance-v09/before-final-64.json)與 [0.9.0](../artifacts/performance-v09/after-final-64.json)。[六張前後畫面的檢視紀錄](../artifacts/performance-v09/visual-review.json)包含 PNG 雜湊；三個固定視角沒有發現可見器材、外殼或人物被錯誤隱藏，但不代表全部相機與動畫格皆已檢查。

## 批次繪製的獨立比較

另以同一個世界、同一姿勢、同一相機切換批次開關，先暖好兩種著色路徑，再按關／開／開／關的順序各測 32 格。分區管理在兩種路徑都啟用。這項測量只隔離批次成本，不能拿來當作完整的新舊版遊戲比較，見 [交錯原始結果](../artifacts/performance-v09/batch-isolation-dirty-uploads.json)。

| 固定姿勢視角 | 批次關閉中位數 | 批次開啟中位數 |
| --- | --- | --- |
| 主場館 | 25.0 ms | 28.5 ms |
| 教室 | 15.0 ms | 14.8 ms |
| 浴室 | 4.9 ms | 2.9 ms |

主場館單獨開批次反而較慢，另兩個視角這輪較快；較早測量的稀疏視角結果也曾相反。減少繪製呼叫仍可能增加每個頂點的矩陣／法向量運算；整版的分區更新節省，與單獨開啟實例繪製的效果，應分開判斷。實體顯示卡的得失還需要原生硬體量測，沒有把呼叫數下降寫成所有裝置必然加速，也沒有依一次軟體繪圖樣本宣稱自動策略已是最佳值。

## 保留的測量限制與診斷

修正冗餘上傳前的 24 格正式診斷仍保留於 [舊版副本測量](../artifacts/performance-v09/before-verified.json)／[當時的本版測量](../artifacts/performance-v09/after-verified.json)：主場館曾量到 32.3 → 43.8 ms，暴露了回歸。其後補上矩陣未變時不重傳、不重算範圍，並以目前 64 格流程重新測量。不同次的軟體繪圖數值也有明顯波動，不能把兩輪的差額全部歸因於這一項修正。

雙頁同時載入新舊版的交錯方案曾遇到軟體繪圖程序持續高負載，未完成有效樣本，已停止；沒有把未完成的流程當成通過的效能證據。最終前後比較各只開一個頁面，獨立比較也只使用一個世界。所有原始中位數及較慢的結果都保留，沒有只挑呼叫數下降的視角。

實作與接點／幾何證據見[分區管理](room-management-v09.md)及[器材批次](equipment-batching-v09.md)。後續若要再降低場館尖峰負載，仍需補人物簡化模型、更多實體硬體測量及真正的模型／貼圖資源卸載；這些未列為本版已完成。
