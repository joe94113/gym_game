# 0.12 遊玩效能前後比較

2026-10-29。這次針對實際走動、奔跑、導航與器材示範減少重複工作。固定畫質下，八種測試情境的平均畫面間隔與超過 25 ms 的畫格比例都下降；多數情境的第 95 百分位仍接近原本，較長的停頓尚未完全解決。

## 這次改了什麼

- **同一人物只計算一份相同骨架。** 原模型的八個 mesh 各持有一份 Skeleton，卻指向相同骨頭與逆矩陣。現在只合併同一人物內完全相等、尚未上傳的 Skeleton，八份變成一份；不同人物仍各自運動。模型、蒙皮、材質、手腳接點、肌群遮罩與動作求解保留。四種外型、三種 LOD 的正式 CPU 比對涵蓋 2,736 個姿勢／LOD 組合、708,624 個蒙皮樣本及 395,952 個完整變形頂點，最大差異為零。見[骨架處理](actor-skeletons-v012.md)與[原始檢查](../artifacts/skeletons-v012/qualification.json)。
- **看不到的電視不再重畫，InBody 只在內容變動時重畫。** 電視保留原尺寸與名義 12 Hz 動畫，轉回視野的同一畫格直接顯示目前播放進度。InBody 保留精確掃描進度，沒有把進度條取整。這減少 Canvas 工作與貼圖更新要求，不能把它全算成實際 GL 上傳的減少；Three 原本也可能略過視野外的貼圖。見[畫面更新](canvas-updates-v012.md)與[CPU 對照](../artifacts/canvas-updates-v012/cpu-qualification.json)。
- **同一次導航搜尋不再反覆取得障礙、檢查相同格子。** 每次搜尋重新取得當下障礙，走路碰撞仍即時查詢。91 條實際場館及門／設備變化路徑，與舊實作的座標陣列完全相同；動態障礙取得次數由 141,761 次降至 91 次。見[導航處理](navigation-search-v012.md)與[原始檢查](../artifacts/navigation-v012/qualification.json)。

場館格局、器材、人物細節、原有 LOD、動畫更新規則、手腳對位、防穿模檢查及紅橘肌群標色均保留。這次沒有調低解析度或關掉陰影來取得前後差異。

## 怎麼測

使用同一台 Intel UHD Graphics 630，以 Chromium 的原生 ANGLE／D3D11 WebGL 執行。舊版為封存的 0.11.0，新版為 0.12.0；[來源凍結紀錄](../artifacts/performance-v012/source-freeze.json)與各輪報告保留來源 SHA，測量期間來源未變動。

| 條件 | 設定 |
| --- | --- |
| 瀏覽器畫面 | 1280 × 800，DPR 1 |
| 流暢優先 `flow` | 固定模式，實際 framebuffer 1088 × 680，保留該模式原設定 |
| 畫面細節 `clear` | 固定模式，實際 framebuffer 1280 × 800，保留原有 2048²、30 Hz 陰影設定 |
| 執行順序 | 舊版第一輪 → 新版第一輪 → 新版第二輪 → 舊版第二輪 |
| 每個情境 | 獨立瀏覽器 context；相同初始站位、朝向及跟隨視角 |
| 測量前 | 15 秒模擬整理快取與場景，再以真實 RAF 暖機 2 秒，均不計入結果 |
| 正式樣本 | 每輪每情境 8 秒真實遊戲 RAF；各版兩輪的原始間隔合併計算 |
| 測量工具 | 關閉 CPU profiler 與 GL 呼叫包裝，`hooks=off`；仍保留輕量 RAF 與位置／畫質紀錄 |

走路與奔跑都從草皮區相同位置開始，以真正的 W／S／W／S 鍵盤輸入走四段；奔跑加按 Shift。走路／導航各輪實際移動約 13～14 公尺，奔跑約 31～32 公尺，沒有把角色瞬移當成移動測試。導航另開啟高位下拉的路線；器材情境持續播放啞鈴臥推。

這裡的畫面間隔是遊戲 `requestAnimationFrame` 回呼的時間差，包含實際更新與瀏覽器排程的影響。它不是獨立 GPU 時間，也沒有使用同步 `world.update()`／`gl.finish()` 的耗時換算 FPS。無頭瀏覽器的合成器可能限制回呼頻率，因此沒有把這些數字宣稱為螢幕實際呈現的 FPS。

## 結果

每欄都是「0.11 舊版 → 0.12 新版」。毫秒和比例越低越好；第 95 百分位表示約 95% 的畫格間隔不超過該值。百分比以畫格數計算，兩輪合併後各情境每版約 16 秒。

| 畫質／情境 | 平均間隔 ms | 第 95 百分位 ms | 超過 25 ms | 超過 50 ms |
| --- | --- | --- | --- | --- |
| 流暢／走路 | 16.46 → 15.78 | 26.8 → 26.7 | 19.38% → 15.04% | 0.21% → 0.20% |
| 流暢／奔跑 | 16.91 → 16.31 | 26.8 → 26.7 | 21.92% → 19.82% | 0.11% → 0.20% |
| 流暢／導航走路 | 15.82 → 15.52 | 26.8 → 26.7 | 15.16% → 14.31% | 0.10% → 0.00% |
| 流暢／啞鈴臥推 | 17.97 → 16.18 | 40.0 → 39.9 | 24.55% → 15.34% | 1.79% → 0.40% |
| 細節／走路 | 28.64 → 26.24 | 53.5 → 53.4 | 56.74% → 46.42% | 20.74% → 17.92% |
| 細節／奔跑 | 30.05 → 26.24 | 66.7 → 53.4 | 58.92% → 46.82% | 23.42% → 17.13% |
| 細節／導航走路 | 34.09 → 28.85 | 66.7 → 66.6 | 77.38% → 57.53% | 23.04% → 18.82% |
| 細節／啞鈴臥推 | 26.39 → 24.15 | 66.7 → 66.6 | 50.08% → 35.04% | 11.99% → 14.29% |

平均間隔在流暢模式下降約 2～10%，細節模式下降約 8～15%。例如流暢模式啞鈴臥推，超過 25 ms 的畫格由 24.55% 降為 15.34%；細節模式奔跑的第 95 百分位由 66.7 ms 降為 53.4 ms。

其餘七列的第 95 百分位只差約 0.1 ms，應視為近乎未變，不能據此宣稱最慢畫格都有改善。超過 50 ms 的比例也有兩列變差：流暢奔跑由 0.11% 升至 0.20%，細節啞鈴臥推由 11.99% 升至 14.29%。新版細節模式仍有約 17～19% 的走動／導航畫格超過 50 ms，這台電腦的高畫質長幀仍是後續優化重點。

這是同一台機器、每版兩輪、固定短路徑的比較，沒有統計顯著性的宣稱，也不是所有硬體的效能保證。首次載入、走近與上下器材、房間切換及全部團課沒有納入這次時間測量；動作與互動另以功能回歸和畫面檢查確認。自動畫質會自行調整負載，因此正式比較只使用兩種固定模式。

前後各 11 張動作圖，共 22 張，涵蓋奔跑三視角、臥推、捲腹、直臂下拉、腿推、舞蹈及左右手近景。11 組配對像素完全相同，已實際檢視[四張比較圖及紀錄](../artifacts/performance-v012/visual/manual-review.json)。原側面手部近景被啞鈴槓片遮住，因此另補左右手的可見角度；這只確認原有握法與外觀保留，沒有重新修正握法或生物力學。骨架的零差異檢查證明這次合併保留既有變形結果；有限姿勢和畫面抽樣不等同真人教練的連續動作簽核，也不能保證所有可能姿勢都不會穿模。
