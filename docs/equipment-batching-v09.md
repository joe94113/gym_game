# 0.9 重複器材批次繪製

0.8 已把每台器材內的固定零件按材質合併；本版沒有把那項既有功能重算成新的優化。新增的是不同器材之間的實例批次：只有幾何所有頂點屬性、索引、分組與繪製範圍逐位元相同，而且使用同一個材質物件，才會一起繪製。

批次以器材所在的 12 公尺格區分。包含蝴蝶機反向模式的 47 個視覺根節點，共有 636 個可批次零件、192 個批次、17 個格區；一般狀態有 610 個零件可見。這裡的可減少繪製次數是結構上限，實際相機的差異以根層固定畫質、相同位置與視角的效能報告為準。

## 保留原機台資料

原本的物件、父子關係、幾何、材質、可見性與手腳接點都保留。批次只把原零件的繪製圖層暫時遮掉，另外用 `InstancedMesh` 畫出相同表面；每次繪製前，依原物件的實際世界矩陣更新實例。因此滑輪、握把、踏板與移動中的鋼架也跟隨原來機構，不另做一套接點動畫。

同一批次只剩一個可見零件時，直接畫原物件。這樣仍是一個繪製呼叫，避免大型合併鋼架在沒有減少呼叫數的情況下，多做每個頂點的實例矩陣與法向量運算。兩個以上才使用實例；切換不改機台狀態，射線也不會重複回傳同一物件。開啟陰影時，計數包含畫面外仍需投影的零件。

可更換的槓片、透明零件、骨架人物與啞鈴動作庫的執行期道具不納入。槓片的片數及重量仍由原機台管理，紅橘肌群標色的人物也維持原來的蒙皮與材質。蝴蝶機只新增 `getBatchRoots()`，讓批次知道正向、反向兩個視覺根節點；沒有更改其動作或幾何。

物件幾何、材質或父節點在執行時被換掉時，對應零件會回到原本的繪製方式。獨立看圖則先呼叫 `suspendRoots()`，暫時讓所選機台直接繪製原物件；離開看圖後恢復批次。射線命中會回傳原機台物件，包含 Three.js 原本會對隱藏物件回傳命中的行為。

## 相機、陰影與更新

批次更新掛在場景的 `onBeforeRender`，使用 Three.js 已更新好的物件矩陣，不多跑一次整個場景的矩陣更新。關閉陰影時，先以當下所有零件的球形範圍計算格區，再剔除畫面外格區；可見零件緊密填入實例矩陣，沒有用縮成零的假隱藏方式提交多餘三角形。範圍來自當下矩陣，因此移動中的握把不會超出舊的範圍而消失。

開啟陰影時保留畫面外的投影物件，避免牆外或畫面外的鋼架突然不再投影；仍由每個格區的實際批次範圍參與相機與光源的裁切。

每個批次重用一份 Float32 暫存陣列，與 GPU 對應的 `instanceMatrix.array` 逐值比較。只有實際 Float32 內容不同時才改陣列、標記上傳；包圍球只在矩陣內容、繪製數量或首次建立時重算。順序變動造成的矩陣重排也會被比對抓到。只有一個可見來源時，暫存資料不會偷偷改動未上傳的矩陣，恢復兩個來源後仍會正確更新。

## 驗證

- `node --test tests/equipment-batching.test.mjs`：十項通過，涵蓋動態父節點、可見性、分格、裁切、陰影、取消批次、獨立看圖、原物件射線、還原、一個→兩個→一個可見來源切換，以及模擬 GPU 版本快取的上傳測試。靜止時版本與包圍球不變，移動、重排、隱藏恢復和單一來源恢復成實例都不漏資料。
- [完整器材報告](../artifacts/performance-v09/equipment-batching-qualification.json)：47 個機台視覺變式，14,039 個循環／進入／離開取樣。啞鈴架只檢查其原本的待機循環與隱藏；玩家啞鈴動作庫不由本模組處理。
- 姿勢、真實接點、握把軸、碰撞體、槓片數量、互動點與機台足跡，在批次開啟／關閉時逐值相同。所有可調負重機台另檢查每側 5／10／20 kg，47 組射線命中比對相同，沒有觸發幾何／材質異常回退；單一可見來源使用原繪製是獨立的效能規則。
- 共 5,228,813 次實際頂點或包圍盒角點比較，以及 3,736,077 次法向量比較。完整頂點／法向量在開始、中點、終點及三個固定相機檢查；其他取樣以八個盒角約束仿射變換的表面誤差。器材批次與原繪製兩種路徑都在範圍內。
- 實例矩陣上傳為 Float32，最大世界位置差為 0.000001502 公尺，約 1.502 微米；最大法向量差 0.00000004372。沒有把這種浮點誤差寫成完全零差，也沒有宣稱這是通用碰撞物理或真人教練驗收。

另有 [實例著色器法向量專項](../artifacts/performance-v09/equipment-instance-normals-qualification.json)，直接依目前 Three.js `defaultnormal_vertex.glsl.js` 的公式計算 `im * (normal / 每欄長度平方)`，再乘批次物件法向矩陣；不是拿一般 inverse-transpose 代替這個實例公式。相同 14,039 個姿勢共檢查 8,524,400 個實例矩陣、25,573,200 個基底法向，以及 3,531,048 個實際頂點法向。另有 70,902 個可見來源採原本法向量著色路徑，分開記錄，沒有假稱它們仍走實例公式。

原機構的三軸最大正規化內積為 5.864×10⁻¹⁶，接近雙精度浮點零；Float32 矩陣的最大正交殘差為 6.786×10⁻⁸。實例著色器公式相對原表面法向量最大差為 4.550×10⁻⁸，基底法向最大差為 4.737×10⁻⁸，沒有發現實際剪切變換，所以不需要為這批已驗證器材回退原繪製。這是 CPU 對實際公式的獨立驗算，不是宣稱已執行 GPU shader 或各種硬體的逐位元結果相同。

本分工沒有執行 GPU 或瀏覽器；實際效能與畫面比較由根層用唯一瀏覽器流程完成。
