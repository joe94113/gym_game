# 手機的渲染預算

手機版先保留玩家、器材動作、接點與紅橘標色，降低畫面解析度和陰影負載。這是渲染設定，不是另一套姿勢或骨架。

裝置判斷使用主要輸入的 coarse pointer、無 hover、觸控點數與視窗尺寸，不靠 Android／iPhone 字串。一般支援觸控但仍以精確滑鼠與 hover 為主要輸入的筆電，維持原桌面設定。這個判斷是操作／負載分類，不代表已辨識實體 GPU 型號或跑過手機效能。

| 設定 | 手機最高 DPR | framebuffer 像素上限 | 動態陰影 |
| --- | ---: | ---: | --- |
| 自動，初始 | 1 | 700,000 | 關閉 |
| 自動，持續慢幀後 | 0.75 | 400,000 | 關閉 |
| 流暢優先 | 0.85 | 500,000 | 關閉 |
| 畫面細節 | 1.25 | 1,050,000 | 開啟，最多 12 Hz 更新 |

實際 DPR 也不會超過裝置 DPR；大視窗會以總像素預算再收斂。橫直切換或調整視窗後重新計算尺寸，持續慢幀的降載會保持到使用者重新選擇畫質，不因短暫恢復而反覆伸縮。

桌面 flow／balanced／clear 原有 DPR、陰影與跑步時陰影更新行為保留。手機的畫面細節仍可手動選，但有明確較低上限，避免 DPR 3 直接產生九倍像素。

`initialRendererConfiguration()` 可在 WebGLRenderer 建立與首次設定尺寸前使用，讓手機初始畫布就遵守預算並關閉 MSAA。`powerPreference` 是瀏覽器的選擇提示，不是電池消耗或 FPS 保證。手機的反鋸齒與較低解析度也有畫面取捨，不能拿它當同畫質的純程式加速。

資料來自 `device-profile-v016.js` 與 `render-quality.js`。純函式與 renderer mock 驗證涵蓋高 DPR、旋轉、像素上限、觸控筆電、單次降載及原桌面設定；瀏覽器模擬和實機數字由本版主驗證另列。
