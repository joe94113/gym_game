# 人物姿勢的矩陣更新

每次解算姿勢前，角色會先同步完整骨架；每當某根骨頭改動，原有程式也會更新它的子樹。0.15 在這段同步流程內直接讀取已更新的世界矩陣，快取角色根節點的反矩陣與旋轉，避免同一姿勢反覆重算祖先。

原有 IK 的運算次序、迭代次數、骨長、手腳目標、手指包握與紅橘肌群材質都保留。函式離開時會停止使用快取，包括發生例外的情況；外部診斷仍會讀取角色的即時變換。這次沒有降低玩家或會員的姿勢更新頻率。

## 等價範圍

使用封存的 0.14 控制器與候選控制器，送入目前 0.15 動作程式產生的相同姿勢，包含已接入的肩推／杯式深蹲動捕節奏。檢查 5,576 個姿勢、每姿勢 53 根骨頭的世界矩陣與局部變換，並逐一比對接點及手腕方向，全部精確相同。輸入動作及其遞迴匯入依賴也記錄來源雜湊。

範圍包含普通器材與啞鈴／滑輪的運動、進出路徑、器材設定端點、六種椅背角度、25 種走跑混合、七種團課動作與整課時點、InBody 站位。角色的位置、方向與整體比例也會輪替。1,142 個姿勢另比對 2,237,128 個實際蒙皮樣本，其中八個代表動作使用 stride 1 的完整皮點，全部相同。

這是同輸入的控制器等價檢查，沒有重新認證教學動作或宣稱所有可能姿勢都不會穿模。報告：[pose-equivalence.json](../artifacts/performance-v015/profile/pose-equivalence.json)。

## 純 CPU 診斷

先建立姿勢，再以舊、新、新、舊的順序，各執行 600 個控制器姿勢。最後來源這一輪平均每姿勢舊版 0.306／0.309 ms，新版 0.188／0.198 ms，合計約少 37.0%。這些數字只描述這台電腦上控制器本身的 CPU 工作，不能直接當成完整遊戲的 FPS 改善。

單次姿勢的矩陣方法呼叫另外在相同 GLB 上實際計數；原始結果見 [pose-call-comparison.json](../artifacts/performance-v015/profile/pose-call-comparison.json)。整體遊玩的改善須以主線另行執行的實際 RAF 前後比較為準。
