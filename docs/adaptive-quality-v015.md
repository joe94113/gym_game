# 自動畫質與最後一輪驗證

同畫質量測顯示，減少角色矩陣與透明字牌的工作後，部分器材示範的 p95 改善，但走動並未全面變快。0.15 因此也調整「自動調整」的負載判斷，保留使用者手動選擇流暢或畫面細節的權利。

原本要平均幀間隔超過 28 ms 才降低負載，可能在頻繁出現較長畫格時仍維持原設定。新版先累積至少 90 個有效畫格，再觀察平均間隔與 33.5 ms 以上畫格的近期比例；累積至少 12 個壓力畫格才改用流暢設定，回穩時會扣減。偶發一次較慢畫格不會觸發。選擇結果保持到使用者重新選畫質，避免解析度反覆跳動。

這個取捨會降低解析度、關閉動態陰影，遠處會員沿用既有流暢模式的細節與更新管理。玩家的動作、接點、器材與紅橘肌群標色保留，說明面板會顯示已自動降低負載。高效能且穩定的環境會繼續使用原本的 balanced 設定；軟體繪圖的初始 fallback 沿用既有規則。

## 和同畫質比較分開看

最初的四輪八情境固定畫質比較與完整 55 項網頁案例，使用修改自動判斷前的 0.15 候選。該來源已逐檔封存於 `.local-tools/v015-fixed-candidate/`，舊原始資料沒有改 SHA 或改標成最後版本已重跑。

最後修訂只改 `render-quality.js` 的自動判斷，以及 `trial-ui.js` 的說明文字。六組手動畫質／DPR、共 3,600 個控制輸入，證明 flow／clear 的原有診斷值、renderer 呼叫、解析度與陰影排程相同，見[手動設定等價](../artifacts/performance-v015/manual-quality-equivalence.json)。

最後來源另通過 195 項 Node、兩種正式建置，以及七個原生網頁複驗：自動降載與手動恢復、空中瑜珈進出、奔跑與畫質、聲音、審查包和 20 秒效能紀錄。這七項是實際重新執行，沒有說成又跑完全部 56 項。固定畫質候選的 55 項結果與一項軟體分區返回保留作前一階段證據。

自動模式另做四輪真實遊玩比較，明確保留實際 active profile 與 framebuffer；若新版改用較低解析度或關閉陰影，就列明這個差異，不宣稱是同畫質的純程式加速。全部數字與原始資料見[效能報告](performance-v015.md)。

本機仍只有 Intel UHD 630，其他顯示卡沒有實機結果；可以用遊戲內的效能紀錄在其他電腦收集，見[硬體測試表](hardware-test-matrix-v015.md)。
