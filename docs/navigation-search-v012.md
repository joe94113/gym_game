# 0.12 導航查詢的重複工作

導引路線會在玩家移動後重新計算。原本 A* 搜尋每次檢查網格時，都重新取得並拼接動態器材障礙陣列；同一個網格也可能被相鄰格子反覆檢查。

這次把查詢集中到 `navigation-search-v012.js`。一次同步搜尋只讀一次動態障礙，並記住這次搜尋已判斷過的格子。下一次搜尋重新取得障礙、建立空的快取，因此開門、換器材與團課配置都會更新。一般走路的 `blocked()` 仍即時讀取障礙，沒有沿用搜尋快取。

A* 的穩定排序、同分先後、四方向順序、0.65 公尺網格、邊界、0.34／0.43 公尺檢查半徑與傳回座標皆保留。人物路徑、動畫、器材接點和碰撞取樣沒有改成較低頻率。

五項 Node 測試檢查原始實作的 SHA、56 個互動點、邊界／同格／小數座標、重複查詢，以及下一次搜尋的門與設備變化。另有[正式數值對照](../artifacts/navigation-v012/qualification.json)：125 個實際場館／器材碰撞框、七扇門、56 個互動終點與 35 組固定種子的門／設備變化，共 91 條路徑與封存實作的座標陣列完全一致。

這 91 次搜尋的動態障礙 getter 次數由 141,761 次降為 91 次；158,223 次網格查詢中，62,748 次使用這次搜尋已有的判斷。這些是工作量計數，不能直接換算為 FPS。遊玩順暢度仍以真實 RAF 的前後比較為準。

`world.getFrameWorkDiagnostics().navigation` 提供累計搜尋與查詢次數，以及最後一次搜尋的快取使用量。測試使用從封存 controller 逐字擷取的獨立 oracle，以及由實際 architecture／equipment 建構器擷取的場館資料；正常測試不依賴 `.local-tools` 或 GPU。
